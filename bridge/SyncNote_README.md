# SyncNote：只读交易历史与复盘同步 EA

SyncNote 给使用网页笔记、复盘和分享的用户使用。用户自行审阅源码、用 MetaEditor 编译，挂一个 EA 即可；不需要 DLL、本机 WebSocket、Python、本地助手或算法交易权限。MT5 和 EA 正常运行时，浏览器关闭也会继续上传历史。

当前版本 **1.014** 修复文本换行自动转为 CRLF 导致授权凭据和历史断点误报写入失败：改用原始 UTF-8 字节写入并核对长度，保留原子替换。

用高对比大字面板替代 MT5 默认小字 Comment，配对码默认 28 号、按钮至少 36px 高，字号可调、窄图表自动换行。可从 EA 属性及图表状态首行核对。新增「EA 图表显示 8 位同步配对码 → 网页填写 → 回 MT5 允许同步」流程，不必先生成长连接码再填 EA 参数。保留近期 K 线补齐、历史断点与严格 ACK；源码打包仍拒绝系统 include 和 `CTrade` 声明，保持只读依赖闭包。

它只上传历史成交、必要的账户/券商标识、货币、同步状态和复盘 K 线；不上传实时余额、净值、持仓快照。原始历史保留所有来源的 deals，包括手动交易、其他 EA、部分平仓、反转以及独立费用/资金变动记录。入金/出金金额本身属于历史敏感数据，不应与“不上传实时余额快照”混淆。

SyncTrade（SyncNote Pro）是另一个产品入口，包含本机交易能力。**不要把 SyncNote 的阻塞 HTTPS 上传代码直接合并进交易事件线程。** 两产品共享的是只读历史模型和分页模块；它们有不同的权限与网络职责。

## 源码文件

```

SyncNoteJson.mqh

```

五个代码文件放在同一目录，所有 include 为相对路径。此包没有系统 DLL 导入、本机监听或任何交易执行函数。旧的单文件采集程序已下线，不再提供下载。

## 安装

1. MT5「文件→打开数据文件夹」，把目录放到 `MQL5/Experts/SyncNote/`。
2. 在 MetaEditor 打开 `SyncNote.mq5`，F7 编译，检查错误和警告。
3. 在 MT5「工具→选项→EA」的 WebRequest 允许地址中添加 `https://sync-trade.top`；自托管时填写自己明确选择的 HTTPS 来源。
4. 将 EA 挂到一个图表，`WebsiteURL` 填同一个网站，`ConnectionCode` 留空。图表显示 8 位同步配对码后，在网页点击「连接 MT5」并填写此码，系统自动识别 EA 类型；不要填到 SyncTrade 的交易配对框。
5. 回 MT5 核对图表显示的同频账号，再点击「允许只读同步」。网页提交成功只代表认领配对请求，还没有上传；EA 收到本地许可并开始上传后，网页才会显示最近同步时间。
6. 配对码 10 分钟内有效。拒绝或过期后，在 EA 点击「重新生成配对码」，再用新码配对。授权凭据只保存在本机，按网站与当前 MT5 账户隔离；重启复用，不必重复填码。可以保持 Algo Trading 关闭；此 EA 不执行交易，也不读取 MT5 密码。

`WebsiteURL` 只接受一个 HTTPS 域名来源，不接受路径、用户信息、通配符、查询串或 HTTP；默认标准 443 端口。只上传到用户在 EA 参数里选定的来源。

## 参数

| 参数 | 默认值 | 作用 |
|---|---|---|
| WebsiteURL | `https://sync-trade.top` | 一个精确可信 HTTPS 来源 |
| ConnectionCode | 空 | 默认使用图表同步配对码；仅旧版兼容时填写网站生成的长采集凭据，不打印到日志 |
| SyncSeconds | 15 | 已准备好批次的上传间隔，失败另作指数退避 |
| HistoryDays | 365 | 首次与周期全量对账范围；1–3650 天 |
| OverlapSeconds | 3600 | 增量窗口向前重叠，补到延迟成交和近期费用修正 |
| ReconcileHours | 24 | 重新扫描完整配置范围的周期，补到更早的历史修正 |
| PanelFontSize | 14 | 面板正文字号（10–24）；配对码双倍字号，窄图表自动换行 |
| UploadBars | true | 当前图表品种的近期四周期 K 线上传；不影响成交历史同步 |

首次历史按时间片和最多 100 条每页分批；首次补录可能持续几分钟。没有交易的时间片会跳过，不为每个空日单独发 HTTP。所有品种、magic、入场/出场类型均保留，云端根据原始记录生成笔记交易摘要。

若起始范围内没有完整开仓上下文，网站必须明确标记无法完整重建，而不是编造开仓价或丢弃原始成交。可增大 HistoryDays 并重新同步；历史早于券商实际可提供的范围时无法保证补齐。

## ACK 与断点

只有 HTTP 200 且响应 `ok=true`、`account_key`、`batch_id` 全部匹配，本地 checkpoint 才推进。网络失败、服务端拒绝、响应解析失败、磁盘短写都不推进。已提交但未收到确认的页面会重试，网站按账户＋deal ticket 去重。

文件保存在 MT5 数据目录 `MQL5/Files/SyncNote/`：

- `binding-<token hash>.txt`：将采集码的 hash 固定绑定到当前账户 key，不保存原始连接码。
- `history-<account hash>-<origin/token/config hash>.state`：已确认的固定范围、游标和完整窗口高水位；校验 checksum 后加载。

checkpoint 使用临时文件写全、FileFlush 后再替换。开始扫描前会先保存计划的固定范围，确认进度仍保持原值；即使首个 ACK 前重启也不会滑动最早边界。写失败时保留原游标；checkpoint 损坏时从配置范围重新扫描，由服务端稳定 key 去重。更换历史天数会使用新的同步作用域，重新补录。

1.001 首次启用持仓起点证据时使用新的 checkpoint 作用域，自动重扫配置历史范围，补齐旧版已上传但无法生成摘要的数据；旧断点文件保留。后续启动仍沿用新断点，不会每次重复全量扫描。每页起点查询失败或单持仓超过 1024 条时明确返回 unavailable/too_large，网站保留原始记录并标记无法完整重建。

账户或服务器变化时清除在途任务并暂停；不会将旧账户的授权用于新账户。同一网站账本已绑定其他账户时，配对确认会拒绝，请先核对个人中心的绑定。不能把两个 MT5 账户混进同一笔记账本。网页解除同步或生成新的旧版连接码会使现有上传凭据失效，需重新配对。

不要在生产终端重复挂多个同账号、同连接码的 SyncNote 实例。不同终端可并发产生重复页面，服务器仍必须独立去重。

## 复盘 K 线

每次成功的历史 ACK 可以附带一个 `review_job`。EA 按服务端给出的精确品种、开平仓服务器时间读取 M1/M5/M15/H1 前后各 30 根窗口，每周期最多 2000 根，上传现有 `/api/mt5/review`。

历史尚未准备好最多作三次本地尝试，之后发送逐周期明确错误；图表上传失败不回滚已经确认的成交历史，任务由云端保留，后续再领取。任务携带的账户、服务器、来源 key（如有）必须与当前绑定一致。

服务器时间原值和当前观察到的 UTC 偏移会分别保留。当前偏移不等于历史夏令时数据库，网站应标记估算时区；不要把跨 DST 的历史显示称为已完全校准。

## 共享行情轨道（1.011）

先获得本次成交上传的精确 ACK 并完成账户绑定，再利用成交同步间隙补行情。M1/M5/M15/H1 轮流检查近 7 天，单次最多 2000 根；之后持续读取新增已收盘 K 线。旧 `SYNCNOTE_BARS_1` 多年回溯断点不会恢复。

CopyRates 的部分返回、内部缺口和空结果都不能证明完整覆盖；仅确认实际上传且服务端接受的行，未证实空窗保留为待补并冷却重试，新增量独立推进。状态里的“近期检查完成”只表示检查过窗口，不表示所有缺口已完整；服务器已有更早历史仍可在网页按需读取。切换品种、账户或站点不会复用别的同步进度。

## 性能与验收边界

上传使用同步 WebRequest。单请求 timeout 配置 5 秒，历史/CopyRates 内部调用也可能等待 MT5 或券商缓存。此 EA 的定位是后台笔记采集，没有本机低延迟交易职责。

共享历史扫描按小时间片工作，最多暂存 1024 个 ticket，分事件排序与序列化。超过密度会缩小时间片；若同一秒超过 1024 条，明确报错、保留游标，不默默跳过记录。处理预算约束自有循环，不能保证 MT5 HistorySelect 本身永不阻塞。

开发环境使用 Windows 自带安装的 MetaEditor64.exe 作离线编译。真实终端挂载、站点白名单、券商历史完整性、断点重启、账号切换、原始资金/手续费记录及四周期复盘上传仍需用户在自己的终端验收。编译成功不证明这些项目已完成，更不代表交易执行已验收（SyncNote 不具备交易能力）。

精确消息字段与共享模块 API 见 [SYNCNOTE_PROTOCOL.md](SYNCNOTE_PROTOCOL.md)。
