# SyncTrade（SyncNote Pro）本机交易 EA

SyncTrade 从 `SyncNoteLocal.mq5` 独立派生，保留旧 EA 文件。当前 1.108 用于 Windows MT5，本机 WebSocket 看盘、市价/限价/止损委托及授权后的成交历史导出。交易必须先完成本机配对授权，配对后取消账户类型及本地额度门槛。源码可编译不等于真实终端验收；本次修复不挂载 EA、不发送订单。

1.108 增加账户品种搜索与切换。`InpSymbol` 为空时初始使用挂载图表品种，也可填写券商精确代码（含后缀）；网页授权后可选择该账户可用品种。实时 tick、四周期 K 线、精度及下单校验一起跟随当前所选品种。挂载图表的 tick 不代表所选品种，定时器独立监测所选品种报价更新。存在未确定结果的交易命令时拒绝切换，不重发订单，也不撤销已有持仓/挂单。

授权后的 `symbols` 请求支持 `request_id`、`offset`（默认 0）、`limit`（默认 100，最多 200），返回 `symbols` 数组、`next_offset` 与 `has_more`；数组保留券商精确 `symbol`、`description`、`path`、`selected`、`trade_mode`、`digits` 和手数规格。`select_symbol` 请求传 `request_id` 与精确 `symbol`，成功先返回同请求标识的 `symbol_selected`，再推送新快照；正在读取的 K 线返回 `SYMBOL_CHANGED`，可重试只读查询。`hello` / `paired` / `snapshot` 的 `features` 增加 `symbols` / `select_symbol`，旧网页仍可使用初始品种。显示别名不参与执行或跨券商 K 线合并。

1.107 修复配对按钮生命周期：只有已输入正确配对码、正在等待本机确认的网页请求才显示“允许本次连接”。成功后隐藏允许按钮及配对码，保留“断开并撤销授权”；重复点击或迟到的按钮事件不会重新生成码或替换有效会话。连接期间不轮换配对码。网页刷新/关闭后，socket 关闭会清理原授权并恢复待连接；异常断网依接收心跳检测，最长约 90 秒后清理。必须由新网页发起配对请求，允许按钮才再次显示；不会自动恢复交易权限。

1.106 同步共享历史分页修复：读取成交时间属性失败，或 HistorySelect 期间切换账户时，返回明确失败并保留游标；不会把异常当作空页确认。

## 安装与权限

将源码包中的 `.mq5` / `.mqh` 文件放在同一目录，在 MetaEditor 编译 SyncTrade。需要允许系统 DLL 导入：Winsock 用于 `127.0.0.1` 监听，bcrypt 用于随机配对码和令牌，Kernel32 提供毫秒 UTC 时钟（Windows 8 及以上）；不需要 Python、额外本机服务或自定义 DLL。

默认来源 `https://sync-trade.top`，端点 `ws://127.0.0.1:18765/ws`，子协议 `tongpin-local.v1`。端口与旧 SyncNoteLocal 相同，二者不能同时监听。网页输入图表上的临时配对码后，仍需用户在 MT5 图表点击授权；断开、撤销、重启或账户切换会使令牌失效。令牌只能留在网页内存，不得上传。

1.106 固定启用 `LOCAL_NO_QUOTAS`，协议返回 `quota_unrestricted:true`：不再要求 `InpAllowTrading`、`InpAllowRealTrading` 或正数单笔/每日限额，也不按模拟、实盘或竞赛账户类型限制交易。旧额度输入保留兼容但不生效，包括单笔手数、品种总敞口、实盘单笔/每日次数与每日亏损；旧图表保存的 false 或零额度不会恢复这些门槛。网页同步取消本模式写死的 1 手上限。券商手数范围/步长、报价与止损规则、点差、滑点、挂单偏离、magic、净额归属、MT5 权限、期限和持久日志检查仍保留。配对和每笔网页确认仍然必需。

`quota_unrestricted` 只表示取消账户类型及额度门槛，不授予净额管理权限；原 `InpUnrestricted` 独立参数及旧语义保持不变。本版无需打开它。升级后核对图表面板、握手 `ea_version` 和文件属性均为 **1.106**。

净额账户默认只允许没有同品种持仓、也没有同品种挂单时的市价开仓，避免反向“开仓”实际上平掉手动仓。净额平仓、改单及创建未来可能影响净持仓的挂单，需要显式 `InpAllowNettingManage=true`；开启后仍受 `InpManageOwnMagicOnly` 限制。确认前与持久日志写入后再次检查持仓和挂单。此检查不能替代券商的原子隔离，避免同时用其他来源修改同一净额品种。

`capabilities` 逐动作声明 `market`、`limit`、`stop`、`close`、`cancel`、`modify`。网页按实际动作授权，不把 `pending` 标签当作所有挂单权限。挂单 SL/TP 相对委托价校验，触发价另按市场价格和券商最小距离校验，明确使用 RETURN 填单策略。券商确认挂单已放置（10008）就结束“放置”命令，订单留在挂单列表，可随后撤销；这不表示已经成交。市价 10008 仍为待回报。

## 每日风控与恢复

1.106 不启用 `InpMaxDailyLoss` 或每日单数限额。旧版限额算法和账本格式继续兼容，持久日志及去重不删除、不重置。

实盘新市价单和挂单的当日次数先写入 `TongpinLocal/quota-<账户摘要>.journal`，再记录执行意图，最后提交。quota 文件按账号与券商服务器隔离、独占锁定并用 SHA 链检查完整性；重挂、重启继续读取。未发送或 OrderSend 明确立即拒绝会释放额度；已接受、已完成或结果未知均保留，后续撤销已接受的挂单不会恢复次数。跨券商午夜的在途请求拒绝并释放旧日预约，需在新日重新确认。

1.106 的预约调用传入 `cap=0`，表示无每日次数上限，仍记录命令预约并拒绝重复命令、无效日期和写入失败。quota 与命令日志损坏或写入失败时禁止交易；保留日志排查，不通过删除文件重试未知结果。原有无 quota 记录的命令不自动补发。

日志继续使用原 `TongpinLocal/commands-<账户散列>.journal` 路径，保留升级前的命令去重与未决结果；不要删除日志以重试未知结果。交易没有自动重发或云端转发。

RETURN 模式的部分成交保持 submitted，直到精确券商订单终止后才确定最终状态和实际成交量；IOC 的部分成交因剩余量取消，可以作为已终止的部分成交处理。期限同时使用真实毫秒 UTC 和接收时的单调计时预算，在持久日志写入后、提交前再次复核；到期后记录拒绝，不执行 OrderSend。升级前已经写成 completed 的旧结果不能凭空恢复当时成交策略，需要在 MT5 中核对，不应通过删除去重日志重下单。

## 历史导出

`hello`、`paired`、`snapshot` 宣布 `product:"SyncTrade"` 和非交易功能 `features:["history"]`。原 `capabilities` 字段继续只表示交易动作。

只有配对后、携带当前 token/account_id/server/epoch 且来自对应连接的 `history` 请求才可读取历史；未配对不暴露账户数据。历史涵盖账户全部品种和 magic，和 `InpSymbol` 的交易范围无关。

请求字段：`type:"history"`、`request_id`、`from`、`to`、`cursor`、`limit`，外加上述授权字段。`from`/`to` 是券商服务器墙钟秒数；单页 `limit` 为 1..100；`from>=1`，单次固定窗口最长 3660 天，建议按 365 天分窗。首次 `cursor:""`，后续原样使用响应游标并保持时间窗不变。响应包含账户绑定、请求标识、`range:{from_server,to_server}`、`deals`、`next_cursor`、`has_more`、`errors`、`time_basis:"broker_server"` 和 `server_offset_sec`、`account_key` 和 `through_server`。错误返回带相同 `request_id` 的 `error`，不推进游标。账户/ticket/position/order 等标识使用字符串。

`server_offset_sec` 只是当前测量偏移，不证明历史夏令时规则。原始服务器时间必须保留，不能将减当前偏移的历史时间声称为已验证 UTC。首次固定 `to` 可用当前 UTC + `paired`/`snapshot` 的偏移；增量拉取须重叠时间窗、按成交 ticket 去重，并在发现券商修正时更新。

历史复盘 K 线使用 `bars` 的可选 `from_server` / `to_server`（必须同时提供）以及 `symbol` / `tf` / `limit`。范围最多 2000 个周期位置、2000 根，支持全部券商品种；响应 `time_basis:"broker_server"`，数组首列保持原服务器秒，不减当前 offset。首次起点会向周期边界取整，以覆盖非整分钟成交。未加载的系列、范围覆盖不足、超限均显式报错，不把缺失数据冒充完整图表。最新 K 线请求保持原有看盘口径和 500 根上限。范围读取与成交分页共用单个回填槽，网页应串行发起，收到 `BARS_BUSY` / `HISTORY_BUSY` 后稍后重试只读查询。

游标不含令牌，绑定原时间窗及最后处理的时间/ticket；网站若保存恢复点，还必须绑定 `account_key`。`through_server` 是已完整扫描到的服务器秒；同秒尚未扫完时不会越过该秒。分页不是券商快照隔离，新增或被券商修订的旧时间成交需要后续重叠补传和按 ticket 更新；禁止把非秘密游标当登录授权。

买卖成交同时导出来自 MT5 持仓历史的真实起点证据。每页缓存、每次 Pump 最多一个新的持仓查询，最多扫描 1024 条；缺失或超限明确标记，不猜开仓价，也不把范围外的原始成交补进当前页。服务器仍验证起点和连续确认覆盖后才重建摘要。

网页每 30 秒回查最近一天；每次完整全量对账后满 24 小时，重新核对 365 天，以补到更早的手续费、隔夜利息和成交修正。未完成的固定范围与游标优先恢复，失败不记为全量完成；旧版浏览器断点在完成当前范围后补一次全量核对。

此 EA 不含云端 HTTP/WebRequest，不自动上传。朋友开启网站的同步选项后，由浏览器异步发送历史；关闭网页后该同步停止。账户切换后必须重新配对，不沿用旧账户上传绑定。

## 性能与验证边界

WebSocket 先处理请求；历史和 K 线批处理协调运行，慢客户端暂停历史输出，交易请求不进入历史队列。历史扫描按每次事件的条目数和耗时预算推进，但 MT5 的 `HistorySelect`/首次历史下载是同步调用，首次全量加载仍可能阻塞 EA 事件线程。不能据此宣称历史导出期间交易永不延迟；应先在 MT5 历史页预加载、分时间窗导出，并在没有交易操作时做首次归档。同步 `OrderSend` 本身也可能阻塞事件处理。

MetaEditor 离线编译只能验证语法和构建。仍需人工在模拟账户检查真实浏览器配对、分页无重漏、账户切换与撤销、慢客户端、未知成交类型和部分平仓，以及所有交易门禁。未经实际验收，不标记实盘可用。
