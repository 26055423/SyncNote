# EA Bridge Protocol v1

Status: stable for v1, localhost-only by default.

The protocol is **NDJSON**: one complete JSON object per line, UTF-8, terminated by a
single LF (`\n`). A line may optionally end in CRLF but senders MUST emit LF only.
There is no framing header and no HTTP layer on the EA socket.

* EA (MQL5) connects to the gateway TCP listener. Default `127.0.0.1:8788`.
* The EA is the **only** component allowed to touch MetaTrader 5. The gateway never
  imports `MetaTrader5` and never uses MT5 IPC.
* Every message is a flat top-level JSON object. `positions` and `orders` snapshots
  contain an `items` array of flat objects; nothing is nested deeper than that.
* Strings are JSON strings. Non-ASCII text may be sent as UTF-8, but the gateway
  serialises commands to the EA with `ensure_ascii=True`, so command bytes are always
  ASCII-safe and cannot split a multi-byte character across TCP reads.

## 1. Transport and limits

| Item | v1 rule |
|---|---|
| Bind address | Gateway binds `127.0.0.1` by default. Do not expose the EA port. |
| Encoding | UTF-8 JSON, one object per LF-terminated line |
| Max line | 4 MiB. Gateway closes a connection that exceeds this. |
| Max command in flight | 128 per connection |
| Handshake timeout | 5 s |
| Heartbeat timeout | 5 s after the last valid `heartbeat` |
| Command timeout | 10 s (REST returns HTTP 504, result is "uncertain") |
| Version | `v: 1`. A mismatched hello is rejected; non-v1 events are ignored/closed. |

TCP preserves order. v1 intentionally has no global sequence number: ordering is
defined by TCP plus the event-specific keys below.

## 2. Handshake

The EA connects and immediately writes exactly one hello line:

```json
{"v":1,"type":"hello","token":"...","terminal":"MetaTrader 5","symbol":"XAUUSD","server_offset_sec":10800,"time":1730000000}
```

Fields:

| Field | Type | Meaning |
|---|---|---|
| `v` | int | Protocol version, must be `1` |
| `type` | string | `"hello"` |
| `token` | string | Shared secret configured in gateway and EA |
| `terminal` | string | Human-readable terminal name/company (free text) |
| `symbol` | string | Trading symbol the EA dedicated chart is streaming |
| `server_offset_sec` | int | Broker/server clock minus UTC, in seconds |
| `time` | int | EA wall-clock time, Unix seconds |

The gateway replies exactly one of:

```json
{"type":"hello_ack","ok":true,"server_time":1730000000123}
```

```json
{"type":"hello_ack","ok":false,"error":"invalid token"}
```

On `ok:false` the gateway closes. The EA must back off and retry. A valid new
connection replaces an older EA connection; commands pending on the old connection
fail with `EA_DISCONNECTED`.

`server_time` is Unix epoch **milliseconds** (wall clock) generated by the gateway.
`time` in hello is seconds to match MT5 `TimeCurrent()`.

After a successful ack the EA MUST send, in this order:

1. `bar` events for the last `InpSnapshotBars` bars of every configured timeframe.
2. one `account` event.
3. one `positions` snapshot.
4. one `orders` snapshot.
5. a `heartbeat`.

Bars may be interleaved with live ticks; all snapshots are authoritative replacement
snapshots, so order within the snapshot set does not matter.

## 3. EA -> Gateway events

All events carry `v` and `type` unless noted. Unknown types are logged and ignored.

### 3.1 tick

```json
{"v":1,"type":"tick","symbol":"XAUUSD","ts_msc":1730000000123,"bid":2650.12,"ask":2650.42,"last":2650.30,"volume":1.0,"flags":6}
```

| Field | Type | Notes |
|---|---|---|
| `ts_msc` | int | MT5 tick time in milliseconds since epoch |
| `bid`,`ask` | number | Positive finite prices |
| `last` | number | 0 if the broker does not publish last |
| `volume` | number | Tick volume; can be fractional (`volume_real`) |
| `flags` | int | MT5 tick flags bitmask |

Ticks are droppable at both ends. The gateway keeps a bounded ring buffer and
coalesces them for browser clients to at most 10 per second per client.

### 3.2 bar

```json
{"v":1,"type":"bar","symbol":"XAUUSD","tf":"1m","bar_time":1729999980,"open":2650.0,"high":2651.0,"low":2649.5,"close":2650.5,"tick_volume":143,"spread":20,"closed":true}
```

* `bar_time` is the **bar open time**, Unix seconds.
* `tf` is one of `1m`, `5m`, `15m`, `1h` (v1 gateway defaults).
* `closed:false` updates the still-forming bar in place.
* `closed:true` is final. A closed bar is written to SQLite by the gateway as soon
  as it is received. Later `closed:false` updates for that same `bar_time` are ignored.
* Key: `(symbol, tf, bar_time)`. The last event for a key wins unless a closed bar
  would be downgraded.

The EA also sends the current open bar from its 1 s timer and sends the just-finished
bar with `closed:true` when it first observes a new bar.

### 3.3 account

```json
{"v":1,"type":"account","login":12345678,"balance":10000.0,"equity":10012.5,"margin":100.0,"free_margin":9912.5,"currency":"USD","leverage":100,"profit":12.5}
```

Flat object, authoritative latest snapshot. The EA sends one every timer tick.

### 3.4 positions snapshot

```json
{"v":1,"type":"positions","items":[{"ticket":123,"symbol":"XAUUSD","side":"buy","volume":0.10,"price_open":2650.0,"sl":2640.0,"tp":2670.0,"profit":12.5,"magic":0,"comment":"bridge","time_msc":1729999999000}]}
```

The entire `items` list replaces the gateway's current list. Required item fields:
`ticket` (int), `symbol` (string), `side` (`buy`/`sell`), `volume` (number),
`price_open` (number), `sl`, `tp`, `profit`, `magic`, `comment`, `time_msc`.
Extra fields are preserved by the gateway and forwarded to clients.

### 3.5 orders snapshot

```json
{"v":1,"type":"orders","items":[{"ticket":456,"symbol":"XAUUSD","type":"buy_limit","side":"buy","volume":0.10,"price":2640.0,"sl":2630.0,"tp":2660.0,"magic":0,"comment":"bridge","time_msc":1729999999000,"state":"placed"}]}
```

The entire list replaces the gateway's current list. Required item fields:
`ticket`, `symbol`, `type` (free string), `side`, `volume`, `price`, `sl`, `tp`,
`magic`, `comment`, `time_msc`, `state`.

### 3.6 trade

```json
{"v":1,"type":"trade","trans_type":2,"order":456,"deal":789,"position":123,"symbol":"XAUUSD","side":"sell","volume":0.10,"price":2655.0,"profit":5.0,"time_msc":1730000000123}
```

`trans_type` is the numeric MT5 `ENUM_TRADE_TRANSACTION_TYPE`. The EA emits one for
`TRADE_TRANSACTION_DEAL_ADD` as soon as the transaction occurs. Fields that do not
apply are `0` / empty. `profit` is the deal profit when MT5 history is available.
Trades are never dropped by the gateway.

### 3.7 heartbeat

```json
{"v":1,"type":"heartbeat","time":1730000000,"server_offset_sec":10800}
```

Sent every second. Any gap > 5 s causes the gateway to close the EA session, fail all
pending commands and mark `ea_connected=false`. The EA reconnects and snapshots.

### 3.8 command result

```json
{"v":1,"type":"result","id":"01J...","ok":true,"retcode":10009,"retcode_name":"TRADE_RETCODE_DONE","order":456,"deal":789,"price":2650.42,"volume":0.10,"error":""}
```

| Field | Type | Notes |
|---|---|---|
| `id` | string | Exact id copied from the command |
| `ok` | bool | `retcode` is `10008`/`10009` (placed/done) and the request succeeded |
| `retcode` | int | MT5 retcode, or a bridge-side synthetic code for local validation |
| `retcode_name` | string | Stable MT5 constant name, e.g. `TRADE_RETCODE_INVALID_STOPS` |
| `order` | int | Order ticket or 0 |
| `deal` | int | Deal ticket or 0 |
| `price` | number | Fill/placement price or 0 |
| `volume` | number | Executed/placed volume or 0 |
| `error` | string | Broker comment or bridge error; empty on success |

Results with an unknown or already-timed-out `id` are ignored. A result is never
retried automatically because order execution may have happened. A REST timeout is
therefore reported as "uncertain" and cached under its idempotency key.

## 4. Gateway -> EA commands

All commands are flat objects with a unique string `id` (UUID in the gateway) and
`type`. The EA returns exactly one `result` with the same id.

### 4.1 order

```json
{"type":"order","id":"uuid","action":"market","side":"buy","symbol":"XAUUSD","volume":0.10,"price":0,"sl":2640.0,"tp":2670.0,"deviation":20,"magic":0,"comment":"ea_bridge"}
```

* `action`: `market` | `limit` | `stop`
* `side`: `buy` | `sell`
* `price`: required and > 0 for `limit`/`stop`; ignored for `market` (MT5 uses the
  current ask for buy and bid for sell).
* `sl`, `tp`: 0 means none.
* `deviation`: slippage in points, clamped by the EA.
* `magic`: integer magic number.
* `comment`: <= 31 chars after truncation by the EA.

### 4.2 cancel

```json
{"type":"cancel","id":"uuid","order_ticket":456}
```

Deletes a pending order. Not valid for an open position.

### 4.3 close

```json
{"type":"close","id":"uuid","position_ticket":123,"volume":0.10}
```

`volume: 0` means close the full position. The EA validates the requested volume
against the live position volume.

### 4.4 modify

```json
{"type":"modify","id":"uuid","ticket":123,"sl":2640.0,"tp":2670.0}
```

For a position the EA sends TRADE_ACTION_SLTP; for a pending order it sends
TRADE_ACTION_MODIFY. At least one of `sl`/`tp` should be non-zero. A zero clears
that protective order.

### 4.5 ping

```json
{"type":"ping","id":"uuid"}
```

The EA replies with a `result`, `retcode: 10009`, no order/deal. Useful for
diagnostics; the REST layer does not need it for health.

## 5. Ordering, reconnect and sequence rules

1. The gateway accepts only one active EA session. A newer authenticated hello
   closes the older socket. Results queued on the old socket are discarded and their
   commands fail; the EA resends snapshots on the new socket.
2. `hello_ack` must be the first gateway line. No commands are sent before it.
3. On reconnect the EA always re-sends the full configured bar window plus account,
   positions and orders snapshots. The gateway treats snapshots as replacements,
   not deltas, and keeps previously received ticks/bars unless a newer bar updates
   them.
4. Bars are keyed by `(symbol, tf, bar_time)` and snapshots may overlap. If a closed
   bar is received again it is idempotently upserted. An open bar can never overwrite
   a closed bar for the same key.
5. Positions/orders snapshots replace the whole list by `ticket`. The gateway emits
   singular `position`/`order` upsert/remove WebSocket events by diffing snapshots.
6. `trade` events are appended, never deduplicated by the gateway. Downstream
   consumers should use `(deal, time_msc)` if they need idempotent ingestion.
7. The gateway watchdog checks every second. More than 5 s without a heartbeat closes
   the socket. The EA detects a dead socket with `SocketIsConnected`/send errors and
   reconnects with a backoff of at least 1 s.
8. Command ids are scoped to one gateway process. A result arriving after its command
   timed out is ignored (the command is uncertain, not retried).
9. Unknown fields are ignored. Unknown message types are logged. Malformed JSON does
   not crash the gateway.

## 6. Backpressure policy

The gateway must never let a slow browser slow down the EA.

* EA -> gateway: the TCP reader always drains. Parsing and in-memory mutation are
  O(message size). SQLite writes happen on a dedicated writer thread.
* Ticks are droppable. If the persistence queue is full, ticks are dropped first and
  a dropped counter increases. Bars, accounts, positions, orders and trades are
  critical and are not silently discarded.
* Browsers: ticks are coalesced to the latest tick per symbol and flushed at most
  every 100 ms (<= 10 updates/s per client). Each WebSocket client has a bounded
  outbound queue. When it is full, the oldest queued message is dropped (ticks are
  already coalesced, so this is stale chart/status data). Clients should re-sync with
  REST after a reconnect or whenever they detect a gap.
* A WebSocket client that cannot accept a message for 15 s is disconnected rather
  than allowing unbounded memory growth.
* Commands are limited to 128 in flight. The gateway rejects new orders with HTTP 503
  when the EA is disconnected or the in-flight limit is reached.

## 7. Security

* The EA listener binds `127.0.0.1` only. Do not expose `--ea-port` publicly.
* MQL5 `Socket*` connections are subject to the terminal's allow-list
  (**Tools > Options > Expert Advisors**). Add `127.0.0.1` there. This is separate
  from, and does not require, any `WebRequest` use.
* The token is compared with `hmac.compare_digest`. It is never logged.
* The gateway web listener also binds `127.0.0.1` by default and has no user auth.
  Put a reverse proxy with authentication in front of it before exposing it.
* Token rotation requires updating both the EA input and the gateway process.
* The EA must be attached to a dedicated chart, one chart per symbol. Running two EAs
  for the same symbol creates duplicate events and duplicate order sources.

## 8. Escaping rules

* Use JSON escapes for `"`, `\`, and control characters (`\n`, `\r`, `\t`, `\b`,
  `\f`, and `\u00XX`). Never place a raw newline inside a JSON string.
* The gateway emits commands with ASCII escapes for non-ASCII characters.
* The EA's minimal parser supports the flat-object subset used here, including
  `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, and `\uXXXX` (surrogate pairs
  included). It does not support nested objects in commands.
* Numbers must be finite JSON numbers: no `NaN`, `Infinity`, leading `+`, or
  hexadecimal.
* Empty strings are allowed for `error` and `comment`; absent optional fields are
  treated as zero/empty by the EA.

## 9. Versioning

`v` is the protocol major version. v1 is closed to new required fields. Additive
optional fields may be introduced without a bump; parsers must ignore unknown fields.
Breaking changes require `v: 2` and a new handshake rejection path.

## 10. Compact examples

EA handshake:

```json
{"v":1,"type":"hello","token":"s3cret","terminal":"MetaTrader 5","symbol":"XAUUSD","server_offset_sec":10800,"time":1730000000}
```

Command:

```json
{"type":"order","id":"6f1c2e2a-1f48-4f9b-9e97-0f6d1e1bc111","action":"market","side":"buy","symbol":"XAUUSD","volume":0.1,"price":0,"sl":2640,"tp":2670,"deviation":20,"magic":0,"comment":"ea_bridge"}
```

Result:

```json
{"v":1,"type":"result","id":"6f1c2e2a-1f48-4f9b-9e97-0f6d1e1bc111","ok":true,"retcode":10009,"retcode_name":"TRADE_RETCODE_DONE","order":456,"deal":789,"price":2650.42,"volume":0.1,"error":""}
```
