# 网页请求 SyncNote 行情区间同步

网页选择品种不会自行取得 MT5 行情。SyncNote 1.016 增加显式的只读区间任务：网页提交品种及 UTC 区间，已授权 EA 轮询并分段读取该券商的精确代码，不要求切换挂载图表。该通道不接收下单或账户操作。

## 请求与状态

- `POST /api/market/sync-jobs`（网站会话）：`{symbol,from,to}`。区间为 UTC 秒 `[from,to)`，最长 365 天；`to` 不能位于未来。品种必须属于本人当前绑定券商目录或同轨已有行情。当前账户一次只允许一个待处理任务。
- `GET /api/market/sync-jobs?symbol=...`：返回 `{job:null}` 或本人当前账户、当前授权的最新任务。
- `POST /api/market/sync-jobs/cancel`：`{job_id}`。取消后晚到的数据不能写入。

任务公开字段为 `job_id,symbol,from,to,status,processed_segments,total_segments,bars_received,last_error,created,updated`，不含账户或凭据。`waiting` 为等待 EA 领取；`running` 为处理中；`completed` 仅表示每个请求周期槽都已有有效 K 线；`partial` 表示扫描结束但仍有未确认空窗或缺失（包括周末、休市或券商无历史）；`cancelled` 为用户取消。分段检查进度不是覆盖完整率，不能把检查到 100% 描述成行情完整。

## EA 协议

`POST /api/mt5/bar-sync/poll` 使用已有 Bearer，正文 `{account,account_key,server}`，返回 `{ok:true,job:null}` 或分段：

```json
{"ok":true,"job":{"job_id":"...","segment_id":"...","account_key":"...","account":"...","server":"...","symbol":"NAS100","tf":"M1","from_server":1,"to_server":2}}
```

分段范围是券商墙钟，起止均包含；周期为 M1/M5/M15/H1，每段最多 2000 个周期槽，只含已收盘 K 线。四周期轮流领取，避免长 M1 区间饿死其他周期。UTC 到墙钟统一调用 `trade_time.offset_for()`，不在网页或 EA 自行给用户输入加减时区。

`POST /api/mt5/bar-sync/result` 提交身份、分段全部字段、`bars` 和可选 `error` 字符串。ACK 精确回显 `job_id,segment_id,account_key,symbol,tf,from_server,to_server,accepted,status`。相同结果重传幂等；同段内容改变、越序、取消、换绑或过期凭据均拒绝。正常 ACK 状态为 `running/completed/partial`。

K 线仍经 `bars.ingest` 写入同一 `(source,symbol,tf,t)` 轨道，只登记真实收到的连续有效行，空窗口不创建整段 empty/have 覆盖。账号撤销或换绑后旧任务对网页不可见，EA 晚到结果也不能写入。EA 不在线时任务保持等待，服务器不会伪造行情或从别的券商补洞。

验证：`python tests/bar_sync_jobs.py` 包含区间端点、跨周期公平分段、严格确认与幂等、空窗/部分历史、取消/撤销、跨账户隔离和无效数据事务回滚；`python tests/smoke.py` 检查站点集成。
