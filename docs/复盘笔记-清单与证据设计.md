# 复盘笔记 V2：交易清查表 → 分项笔记 → 图表证据

本文整合两轮讨论的结论，是 [自由复盘笔记与模板开发方案.md](自由复盘笔记与模板开发方案.md)（第一版）之后的**整合稿**。
第一版已上线的能力（自由条目、个人模板、常用语、推荐）不推翻，本文只在其上扩展。

一句话：**输入用分组清单，输出用总结视图，中间靠证据串起来。**

> 进度：M6 已上线——复盘摘要（只读、可复制）+ 统计（已复盘笔数、结论分布、最常跳过项）+ 分享时冻结笔记快照，收件人看到分享当时的内容。
> M5 已上线——条目可挂图表证据（从当前图的画线里挑），证据卡显示 ① 编号，悬停高亮原图、点击跳到对应周期与位置；模板不保存证据。
> M4 已上线——公开模板库：发布（只带结构与提示语）、撤回、搜索、收藏、引用为个人副本；计数与收藏按人去重。
> M3 已上线——模板可固定（★ 排最前）、空笔记优先提示「上次用的组合」一键套用、结构可复用时提示存为模板。
> M2 已上线——常用语分三层（系统 / 我的 / 当前模板）、插入到光标处、选中文字存为常用语、常用语可固定到前面、计数 5 秒内去重；模板可带常用语。
> M1 已上线——`sections` 支持 `group` / `verdict`，面板改为分组卡片 + 结论点 + 折叠 + 完成度，新增「＋ 通用清单」；模板保存会保留分组、清空结论。M2（常用语三层）未开始。

- 不要用思维导图当编辑器：复盘时是「逐项打勾 + 写两句」的线性动作，脑图适合结束后归纳。
- 不要按流派分模板（SMC / 缠论 / 谐波）：多体系融合是常态，模板是用户自己组合出来的**条目清单**，不是系统给的分类。
- 不要用「没勾」表达两件事：是否检查过（checked）与条件是否成立（verdict）必须分开。

---

## 1. 三层模型

| 层次 | 用户可以做什么 | 存储 |
|---|---|---|
| 条目 | 自己命名、增删、拖动排序（“先看大方向”“这次又急了”） | `sections[]` |
| 条目内容 | 勾选、结论、文字、常用语、图表证据 | section 内的字段 |
| 整套模板 | 保存条目组合并命名；每次复盘也能临时调整 | `journal_templates` |

同一份 `NoteSection` 既能当清单项、也能当自由条目——区别只在有没有 `group`。
这样“自由度高”和“有结构”不冲突：系统给起点，用户改着改着就长成自己的体系。

```json
{
  "id": "sec_xxx",
  "group": "结构与流动性",          // 可空；空 = 自由条目，不进完成度分母
  "title": "扫低后出现 Flip",
  "checked": true,                  // 已检查 ≠ 条件成立
  "verdict": "yes",                 // yes | no | unclear | na，默认 null
  "body": "扫 4092 低点后假突破，回踩没破。",
  "evidence": ["ev_xxx"],           // 指向图表证据
  "collapsed": false,               // 纯前端态，可不入库
  "updated": 1762000000
}
```

老数据没有 `group` / `verdict` / `evidence` 时按旧行为渲染，与第一版「老客户端不带 sections 不清空」是同一套兼容策略。

## 2. 复盘面板

```
复盘 #43349737                          完成 4/7
模板：SMC 日内交易 ▾                              ← 仅作为一个已保存组合的名字，不带流派语义

✓ 方向判断                                        偏多    ← 结论点
  日线看多，1H 回踩需求区。

✓ 结构与流动性
  [扫了低点] [拿了 IDM] [＋ 常用词]                      ← 常用语 chips，插入光标处
  扫低后出现 Flip，等待回踩确认。
  ↳ 证据 ① 扫低标记   ② Flip 水平线                    ← 证据卡，悬停高亮/点击定位

✓ 入场位置
  [触及 POI] [FVG 被缓解]
  回到 15m POI，与前低重合。

▸ 入场模型
▸ 止损与仓位
▸ 订单管理
▸ 结果与改进

                                  [保存复盘] [存为模板]
```

要点：

1. **一行 = 勾选框 + 标题 + 结论点 + 证据数**，未展开时也能一眼扫完。
2. 展开才出现文本框与常用语，避免 30 项时页面过长。
3. 「完成 4/7」的分母只算 `group` 非空且未被设为「不适用」的项；自由条目不进分母。
4. 组默认顺序：方向 → 位置 → 确认 → 执行 → 管理 → 复盘；每个模板可调整，组内可拖动。
5. 结论点只用四个值，避免自由文本无法统计：
   `符合 / 不符合 / 不确定 / 不适用`，未选则显示为「—」。
6. 「没勾」= 还没看；「勾了但没选结论」= 看过、尚未判断。两者在 UI 上不同，在统计里也不同。

## 3. 常用语分三层

| 层 | 来源 | 作用 |
|---|---|---|
| 系统词库 | 内置（扫了低点、拿了 IDM、FVG 被缓解、出现 Flip…） | 新用户第一次就有东西可点 |
| 我的常用语 | 用户保存 | 跨模板复用 |
| 当前模板用语 | 模板自带 | 换模板时自动切换语境 |

- 插入到**光标位置**，不是一律追加到结尾。
- **选中一段文字 → 存为常用语**（比现在存整段正文更符合实际）。
- 每层都按使用次数 + 最近使用排序，收藏/固定的永远排前面（位置稳定，不每天变）。

---

## 4. 模板：个人组合 + 显式发布

- 模板只存**结构**：条目标题、分组、顺序、提示语、常用语；正文与勾选一律清空。
- 新建复盘时优先给「最近使用的组合」，但不自动套用。
- 连续几次用了同样几个条目，提示「要不要存成模板」——由用户决定。
- 推荐分三类分别做：条目、常用语、整套组合；计频要**去重 + 限流**（现在的 `/api/journal/library/use` 可被脚本刷）。
- 收藏、固定顺序优先于频率。

公开部分：不做「手动发布模板」，改成**全服条目词云**。

- 只聚合**条目标题**，按「有正文或已勾选」的已保存复盘统计；一笔交易同一标题只算一次，
  人数按用户去重，另给使用笔数。
- 词云只返回 `标题 / 使用人数 / 使用笔数 / 最常见分组`，**不含任何用户、交易、正文信息**。
- 点一个词 = 把这一章加进自己的清单（自动带上它最常见的分组），也可一键改名后再用。
- 不设发布、撤回、举报；不做公开模板整体引用——模板仍是个人私有。
- 用了的人越多字号越大，10 秒内可手动刷新；筛选框只过滤本地已拿到的标题。

## 5. 图表证据：显式关联

1. 在矩形/水平线等图形上填标题与注释。
2. 图形上点「关联到复盘」，选择「入场位置」这类条目。
3. 笔记里出现证据卡：`① 15m 需求区：首次回踩`。
4. **悬停只高亮，点击才跳周期/位置**——阅读笔记时画面不跳动。
5. 图形注释改了，笔记里提示「更新到笔记」，由用户选择，绝不自动覆盖已整理的文字。
6. 关联时存 `drawing_snapshot`：图后来被移动或删除，复盘仍能看懂当时的依据，并标记「原图已改动」。

证据字段：

```json
{
  "id": "ev_xxx",
  "section_id": "sec_xxx",
  "symbol": "XAUUSD",
  "source": "srv:xxx",
  "timeframe": "M15",
  "anchor_ms": 1761998400000,
  "drawing_id": "d_xxx",
  "caption": "15m 需求区：首次回踩",
  "snapshot": { "...SerializedDrawing" },
  "snapshot_version": 1
}
```

已核对当前 Vela 0.9.3 能力（`web/chart-src/node_modules/@luxalgo/vela`）：

| 能力 | API | 结论 |
|---|---|---|
| 图形 ID | `drawing:created` 事件 | 可作为证据主键 |
| 读写图形 | `chart.drawings.add/update/remove(id)` | 可用 |
| 高亮 | `chart.drawings.select(ids)` | 可用，但会同时打开图形工具条，悬停场景偏吵 |
| 图形文本 | `SerializedDrawing.text` / `props` | 可存注释 |
| 存档 | `toJSON/fromJSON` | 可做快照 |

因此：**第一阶段只做「点击定位」**；悬停高亮用应用层描边覆盖层实现，或接受 `select()` 附带打开工具条的行为，先验证再决定。

## 6. 总结视图（写完才用）

- 由已点亮的条目 + 结论 + 证据生成：一段可复制的复盘摘要，或一张只读脑图。
- 脑图节点 = 条目（+ 证据）；**不另存第二套正文**，改动仍回到清单里改。
- 摘要里明确标「由清单生成」，模型生成的内容（如果将来引入）要标来源、可编辑，不能记成用户已勾选。

---

## 7. 统计（结论字段的结构化目的）

有了 `checked` + `verdict`，无需额外埋点即可算：

- 完成率：已检查 / 应检查（排除不适用）
- 最常跳过项：`checked=false` 比例最高的条目标题
- 最常命中项与最常不成立项
- 结论分布：符合 / 不符合 / 不确定
- 按品种、周期、模板分组对比

统计口径必须与「已复盘」判定一致：只统计真正保存过的复盘（条目有正文或勾选）。

## 8. 交付节奏

| 阶段 | 交付 | 验收重点 |
|---|---|---|
| M1 | 清单分组 + 结论点 + 折叠 + 完成度；默认一组可删改的通用清单 | 用户能否在 60 秒内记完一笔；不勾也能保存 |
| M2 | 常用语三层 + 光标插入 + 选中文本存为常用语 | 插入后仍能补充具体时间/周期/依据，不是只剩标签 |
| M3 | 保存为模板 / 套用 / 推荐（先私有） | 套用不覆盖、不自动应用 |
| M4 | 公开模板库（发布、版本、撤回、防刷） | 发布内容不含任何交易信息 |
| M5 | 图形注释 + 显式关联 + 证据卡 + 点击定位 | 关联后移动/删除图形仍可读 |
| M6 | 悬停高亮 + 分享冻结证据 + 总结视图 + 统计 | 分享卡片看到的是分享当时的笔记与证据 |

M1 最值得先做：不依赖图形能力，能直接验证「用户愿不愿意按流程记录」。若 M1 的实际填写习惯显示大家只写一两项，再决定脑图是否值得做。

---

## 9. 明确不做

- 不做流派分类、不做「你属于哪一派」推断。
- 不把勾选当结论，也不把结论当「交易有效」。
- 不在悬停时移动图表、不把高亮写进画线存档。
- 不自动套用模板、不自动重排已有条目。
- 不让公开模板携带正文、交易号、账户或私有图表。
- 不为了思维导图另存一份正文。

---

## 10. 待定

1. 结论点的默认值：留空（强迫判断）还是「不确定」（降低摩擦）。
2. 「不适用」是否仍要求写一句理由。
3. 完成度是否把自由条目计入（当前建议：不计）。
4. 模板里是否允许保存常用语（建议允许，作为「当前模板用语」）。
5. 脑图是内嵌面板还是导出图片/链接。
