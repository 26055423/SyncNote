# 自由复盘笔记与个人模板

## 产品目标

让交易员自由组织自己的笔记章节、检查项、常用表达和图表证据。章节像文章标题，可以自己命名和排序，也可以混合多种交易方法。系统不设置 SMC、缠论等流派分类，不推断用户属于哪一类交易员。

第一版实现章节笔记、个人模板、常用语和个人频次推荐。图形证据联动、公开模板库和总结视图为后续工作，不能把本文中的设计视为已经上线的能力。

## 已确定的交互约定

- 原来的自由正文与标签保留，章节不是迁移或删除旧正文的理由。
- 每个章节有稳定 ID、可修改的标题、已检查复选框、正文；可以增加、删除、上移、下移。
- 勾选表示用户检查过此项，不代表条件成立、交易有效或系统审核通过。未来若增加结论，单独存“符合／不符合／不确定／不适用”。
- 从空白开始，也可手动选通用章节作为起点；不强制清查顺序。
- “保存笔记”保存这次交易内容。“保存为模板”保存命名后的章节结构，默认清空正文和勾选状态。
- 套用模板追加章节，生成新的章节 ID，不覆盖已有正文或已有章节。不自动套用最高频模板。
- 常用语点击后插入用户选定的章节；用户可以补充文字，并可以保存自己的常用语。
- 现有笔记中的标题、顺序和内容永远不因推荐结果变化而自动重排。
- 个人模板、常用语默认私有，不因“保存”而发布给其他用户。

## 第一版数据与接口

章节结构：

```json
{"id":"stable-section-id","title":"这笔为什么敢进","checked":true,"body":"扫低后出现 Flip，等待回踩确认。"}
```

保留 `trade_notes` 的五列结构，新增配套章节表，避免旧客户端和演示数据的五列 INSERT 失效。笔记读取接口在原有 body/tags/updated 外返回 sections。旧客户端保存时缺少 sections，必须保留已有章节；显式 sections=[] 才表示清空。

| 接口 | 用途 |
|---|---|
| GET /api/journal | 原有笔记读取，附加 sections |
| POST /api/journal | 原有保存，支持 sections |
| GET /api/journal/library | 本人的模板、常用语、常用章节 |
| POST /api/journal/templates | 创建或修改本人命名模板 |
| POST /api/journal/phrases | 保存常用语，避免重复创建 |
| POST /api/journal/library/use | 用户实际套用模板或使用常用语时记一次 |
| POST /api/journal/library/remove | 删除本人模板或常用语 |

模板项返回 id/name/sections/uses/last_used；常用语返回 id/text/uses/last_used；章节推荐返回 title/uses/last_used。所有所有者从登录会话确定，不信任请求中的 person/user_id。外人的模板 ID 不能读取、覆盖、计频或删除。

常用章节按有内容或已检查的已保存笔记计算，一笔交易同标题只算一次。反复保存同一笔交易不增加次数。空章节、只套用但没有填写的模板不计入“已复盘”；有章节正文或实际勾选才计入。保留原来的正文和画线判定。

模板推荐首先按个人使用次数，其次按最近使用排序，排序只影响候选列表。未来加入固定、收藏与时间衰减时，应保持已有笔记顺序不变，并为用户保留手动选择权。

## 第一版验收

1. 旧笔记原样打开、编辑、保存；旧 API 客户端不会清空章节。
2. 自定义标题支持中文、混合体系和任意顺序；勾选、章节正文刷新后保留。
3. 保存结构模板后，套用到另一笔交易时正文、勾选为空，ID 与原笔记不同。
4. 套用模板不会覆盖当前笔记，删除或调整章节不会改动模板。
5. 自定义常用语可以保存、插入和删除；只有本人能管理。
6. 有未保存章节改动时，切换交易、刷新或离开页面有提示。
7. 保存请求进行中继续编辑，返回的旧结果不能覆盖新输入；切换交易后旧响应不能写入新交易。
8. 分享或好友查看沿用现有复盘权限，章节只读；私有模板库不随笔记一起发送。
9. 空结构不产生“已复盘”，正文或章节内容保存后交易历史、日历采用同一个判定。
10. 完成前跑新增后端测试、前端模型测试、前端构建和 tests/smoke.py；用本地演示账号验证操作与刷新，不能只证明 HTTP 200。

## 第二阶段：图表证据

### 关联方式

在图形属性中填写标题/注释，通过“关联到复盘”明确选择章节。笔记里展示编号证据卡。悬停只高亮；点击才定位周期、时间并激活图格，避免阅读文字时图表不停跳动。鼠标移出恢复原样，不能把高亮效果写进画线存档。

建议证据字段：id、section_id、symbol、source、timeframe、anchor_ms、drawing_id、drawing_snapshot、caption、snapshot_version。使用券商 source 和品种精确标识，时间统一 UTC，显示走 stamp()。不能仅凭绘图数组位置关联。

Vela 绘图 ID、读取/更新/选中 API 必须先依据当前安装版本验证；不在库没有公开能力时读写私有 renderer 状态。必要时实现应用层临时覆盖层，不能改写用户原图形颜色实现高亮。

### 快照与更新

关联时保留独立图形快照。图形后来被移动或删除，历史复盘仍能理解当时依据；标记“原图形已修改／删除”，允许查看快照。图表注释更新后提示用户同步到笔记，不自动覆盖手写正文。

图表证据必须随分享切片冻结，收件人只能读其获准的快照。现有 review_shares 按 owner/ticket/recipient 复用记录的限制必须先解决，才能承诺每条旧分享始终显示原始证据。

## 第三阶段：公开模板与推荐

- 增加明确的“发布到模板库”，发布前预览内容与可见范围。
- 公开内容采用独立对象和版本，只包括用户明确选择的章节/提示语，不带交易号、账户、私有图表或原始复盘正文。
- 可以取一个章节，也可以复制整套；引用后是个人副本，上游更新不会改变既有笔记。
- 不按流派分类；允许自由名称、搜索和可选自定义描述。
- 推荐以个人已使用内容为主，公开库根据明确的收藏、使用与反馈逐步完善，不能把私有使用记录公开。
- 推荐计频要限流和去重，防止反复点击刷次数。发布、撤回、举报、版本兼容和授权校验完成后再开放公共推荐。

## 总结视图

后续可提供折叠大纲或思维导图作为同一份笔记的另一种展示。每个节点映射稳定 section_id，图表证据挂在章节下；不另存第二套正文，避免两种视图相互覆盖。自动总结若引入模型，应保留来源、允许编辑，不把模型生成的判断记为用户已检查。
