# 本机 EA 交易架构设计

日期：2026-10-30。本文记录已确定的目标架构、首版实施边界和验收要求；代码部署成功不等于真实 MT5 交易验收通过。

## 1. 已确定的方向

同频网站分发 UI，用户在自己的 MT5 中登录券商账户，自行审阅和编译开源 EA。浏览器通过本机 WebSocket 连接 EA，行情和交易请求不经同频服务器转发。

- 用户只需 MT5、浏览器和 EA 源码；不要求另装 Python、Node、本机代理程序或自定义 DLL。
- 第一版支持原生 Windows MT5，浏览器优先 Chrome / Edge；浏览器与 MT5 必须在同一台电脑。
- EA 可以调用公开列明用途的 Windows 系统 DLL，需要用户开启 DLL 导入权限。
- MT5 密码由 MT5 自己管理。网站不收集、不保存、不转发券商密码。
- EA 默认只读；用户在 EA 本地决定交易权限、品种和限额。
- 首版交易硬性限定模拟账户；实盘账户保持只读，不提供网页绕过开关。实盘支持需在模拟账户验收后另行评审。
- 云端复盘与分享保留。新增本机连接不会自动上传本机账户、持仓、成交或行情。

用户自行编译的是 `.mq5` / `.mqh` EA 源码，并非 MT5 客户端源码。公开源码提供审阅和自主构建的条件，不代表自动完成安全审计。

## 2. 拓扑与职责

```mermaid
flowchart LR
    Cloud[同频网站：登录 / UI / 复盘 / 好友] -->|HTTPS 分发静态资源| Browser[用户浏览器]
    Browser <-->|127.0.0.1 WebSocket| EA[用户自行编译的本机 EA]
    EA <-->|MT5 交易连接| Broker[用户券商服务器]
    Browser -.->|用户选择开启后，异步上传| Cloud
```

| 组件 | 职责 | 不承担的职责 |
|---|---|---|
| 网站 Python 服务 | 网站账号、UI 分发、源码下载、已有复盘与社区接口 | 不保管券商密码、不代理本机交易命令 |
| 浏览器 | 本机连接、行情缓存、图表和交易表单、展示真实回报 | 不决定最终交易权限、不承诺订单已成交 |
| 本机 EA | WebSocket 服务、配对、账户绑定、最终校验、订单执行和状态查询 | 不运行网页下发的脚本、不自动接收云端交易命令 |
| MT5 / 券商 | 账户认证、交易权限、保证金和执行、订单与成交事实 | 同频 UI 不替代它们的最终状态 |

网站登录会话、本机 EA 会话、已有云端采集连接码为三种独立凭据，禁止互相代用。

## 3. 当前仓库与复用范围

本节依据 2026-10-30 当前源码重新核对，覆盖本次新迁入的 `bridge/`。`docs/架构说明.md` 主要记录原有运行架构。

| 当前文件 | 已有实现 | 目标架构中的处理 |
|---|---|---|
| `bridge/WebBridge.mq5` | 原生 Socket TCP 客户端，tick/bar/账户/持仓/订单、`OrderSend`、开仓/撤单/平仓/改单 | 复用数据和交易语义，保留原文件；新 EA 单独实现本机监听与授权 |
| `bridge/gateway.py` | 独立 Python 网关、REST 交易、行情 WebSocket、部分限额和幂等 | 保留给已有用户；新方案的终端用户不需要运行它 |
| `bridge/PROTOCOL.md` | EA → 网关 NDJSON v1 | 保持兼容，不把原 TCP 协议冒充浏览器 WebSocket |
| `web/TongpinSync.mq5` | 只读 HTTP 上传，默认 5 秒 | 继续作为旧采集方式，不承担本机交易 |
| `ea_hub.py` | EA → 云端的采集连接，未提供网站交易命令通道 | 不作为新方案的交易转发器 |
| `tools/bridge_push.py` | 每轮默认等待 5 秒，读取网关再上传云端 | 旧同步方式继续可用；不属于新方案必装组件 |
| `web/chart-src/src/App.tsx` / `vela/provider.ts` | 图表和实时行情的秒级 HTTP 轮询 | 本机模式使用共用连接和缓存；云端复盘保留原来源 |
| `app_server.py` | 网站路由、静态文件、CSP | 添加源码下载和安装说明；精确允许本机连接地址 |

原 `WebBridge` 在 `OnTick` 和每秒 `OnTimer` 收取命令，使用同步 `OrderSend`。无 tick 时会受一秒定时器影响；交易请求还可能阻塞同一 EA 的后续事件。不能据此宣称已实现毫秒级网页交易。

原 gateway 的部分业务限额在 Python 中，新 EA 必须在本地重新实现，不能只复制执行函数。原 gateway 的网页 REST / WS 也不能直接视为完成了公网网站的来源校验和本机配对。

## 4. 为什么 EA 需要系统 DLL

MQL5 官方原生网络接口提供主动连接和读写，没有服务端所需的 `bind/listen/accept`。浏览器也不提供任意 TCP 客户端。因此仅将已有 EA 的端口填入网页不能工作。

新 EA 使用 Windows 自带的 Winsock（`Ws2_32.dll`）实现回环 TCP 监听，在 MQL5 层完成 HTTP Upgrade 与 WebSocket 帧解析。随机配对码和会话密钥使用系统密码学随机源，禁止以时间戳或 `MathRand` 作为授权凭据随机源。具体 DLL 导入、参数和用途须随源码公开。

这是一项实现方案，需要在实际 MT5 编译器和浏览器上验证。不得把“无需自定义 DLL”表述为“无需 DLL 权限”，也不得声称系统 DLL 调用没有风险。

第一版不包含 Wine/macOS、MT5 内置虚拟主机、手机直连电脑或 VPS、自动发现局域网终端。若后续禁止 DLL 导入，需要改为独立本机服务或云端长连接，是另一种交付方式。

## 5. 安装、配对和撤销

1. 用户从网站下载源码包，检查源码和发布版本，在 MetaEditor 编译 `TongpinLocal.mq5`。
2. 在专用图表挂载 EA，核对允许的网站 Origin、品种和本机端口。默认仅查看，启用交易须在 EA 本地设置。
3. EA 仅监听 `127.0.0.1:18765`，展示一次性 8 位配对码。建议有效期 120 秒，最多尝试 5 次，超限作废并等待用户在本地重新生成。
4. 用户登录网站，点击“连接本机 MT5”，接受浏览器本机网络访问提示，在网页输入配对码。
5. EA 显示请求的网站来源和当前账户；用户点击 EA 图表中的授权按钮后发放高熵会话令牌。配对成功前不得返回私人账户明细、持仓或历史。
6. 网页会话令牌默认仅存内存，刷新或断开后重新配对；不得写入 URL、云端数据库、分析日志或浏览器持久存储。
7. EA 本地撤销、账户切换、EA 重启均使令牌失效；网站退出登录时主动断开本机会话。关闭网站不会撤销券商已接受的订单。

允许来源使用完整的 scheme + host + port 精确匹配；生产默认 `https://sync-trade.top`。本地开发 Origin 必须由用户显式配置，不使用通配符。缺失 Origin、`Origin: null`、来源不符、Host/端口不符均拒绝。会话绑定 EA 实例、券商服务器、账户和本次运行 epoch。

一个 EA 实例第一版只允许一个已配对的活动客户端。第二个标签页需要显式接管或提示已有连接，不静默夺取交易会话。多 MT5 实例使用不同端口，并分别配对，不通过扫描任意端口发现账户。

## 6. 本机协议与数据模型

独立命名 `tongpin-local` v1，WebSocket 子协议 `tongpin-local.v1`，端点 `ws://127.0.0.1:18765/ws`。实际字段与响应定义由 `bridge/LOCAL_PROTOCOL.md` 固定；开发时网页和 EA 必须同版本联调。

消息至少覆盖以下语义：

| 消息 | 作用 |
|---|---|
| `hello` / `pair` / `paired` | 协议协商、配对、本地确认和令牌发放 |
| `snapshot` | 授权后账户、持仓、挂单和最新价格快照 |
| `tick` / `bars` / `trade` | 行情、历史和变化事件；首次快照与增量更新分开 |
| `command` / `command_result` | 请求交易及其阶段性/最终回报 |
| `command_status` | 按原 command_id 查询，不创建新交易 |
| `ping` / `pong` / `error` | 存活、往返延迟和明确拒绝原因 |

首版操作以 EA 宣布的能力为准：市场买卖、按 ticket 平仓、撤销挂单、修改止损止盈。挂单新建、批量操作、策略执行不因旧 gateway 支持就默认开放。

所有账户号、order/deal/position ticket 用字符串，避免 JavaScript 大整数精度丢失。价格和手数按品种精度与 volume step 校验，不能固定保留两位。券商品种原名（如后缀 `.m`）必须完整保留。

命令包含 `command_id`、账户绑定字段、目标动作、请求参数和有效期；绝对时间需要先根据 EA 的握手时间估计偏差，EA 内部使用单调时钟限制排队与会话寿命。拒绝不合理的未来截止时间，不让网页无限延长命令有效期。

K 线以 `(账户/实例、symbol、tf、bar_time)` 标识；首次历史分页/分批，当前 K 线更新原记录。明确区分 UTC 时间与券商墙钟：保留原始时间、转换依据和 offset，禁止对已转换的 UTC 再减一次时差；历史跨夏令时不能仅用当前 offset 当作完整时区规则。

## 7. EA 最终权限与订单生命周期

EA 本地参数控制：总交易开关、品种白名单、最大单笔手数、最大滑点，以及开仓/平仓/撤单/改单分别允许与否。检查券商 min/max/step、交易时段与权限、保证金、SL/TP 规则和账户绑定。风险限额不能通过网页命令放宽。

明确目标 ticket 和账户后再操作。第一版仅允许管理本 EA 创建或用户在本地明确授权的订单/持仓；手动仓位和其他 EA 的仓位不得默认授权。在净额账户中同品种仓位可能合并，不能仅凭 magic 号声称完整隔离，因此首版净额账户硬性只读，仅模拟套期保值（对冲）账户可以在本地开启交易。

交易状态按以下含义展示：

```text
网页创建请求 → EA 校验 → 记录提交意图 → 调用 MT5 → 券商回报 → 订单/成交核对
                    ↘ 拒绝               ↘ 超时/断线：结果待核实
```

- EA 收到请求不等于已发送，已发送不等于券商已接受，已接受不等于全部成交。
- 市价部分成交、挂单创建、撤单、SL/TP 更新各有独立结果，禁止将所有成功 retcode 都显示为“已成交”。
- 首版可保留同步 `OrderSend`，明确其会阻塞 EA 事件；若改用 `OrderSendAsync`，必须实现 request_id 与 `OnTradeTransaction` 关联，不以函数返回 true 作为成交凭证。
- 全部交易动作统一 command_id + 请求指纹去重。相同 ID / 相同内容返回已有状态，相同 ID / 不同内容拒绝。
- 调用 MT5 前记录本地提交意图，回报后记录关联订单与成交；重启恢复时未能核实的记录保持 uncertain，不自动重新执行。
- 本地文件写入和券商提交之间没有原子事务。即便有日志，也不承诺跨崩溃端到端 exactly-once；宁可保留待人工核实状态，也不因找不到匹配成交就重发。
- 网页超时、WS 断线、页面重载均不自动重放交易命令；新页面先拉快照、查原 command_id。网页没有离线交易队列。

止损止盈一旦由券商接受可按券商规则继续生效；网页条件触发、移动止损等功能若未来加入，必须说明依赖哪个运行进程，不能混为服务器托管订单。

## 8. WebSocket 服务约束

网络循环采用非阻塞 sockets，每次处理限定字节数、帧数和耗时。支持 HTTP 头分包、WebSocket 客户端 masking、分片文本消息、ping/pong/close、部分发送和背压；非法帧、超限头/消息、无效 UTF-8、非预期二进制消息需要明确拒绝。

回环监听不是授权机制：先校验来源与配对，再允许查询和交易。未授权客户端只能进行有限的协议握手和配对，不能读账户与行情。会话令牌不使用网站 Cookie。WS 来源校验独立于 HTTP CORS。

行情按品种合并最新值；历史快照拆批发送。交易回报和状态变更不得被行情队列静默丢弃。慢客户端达到队列上限时停止历史输出或断开，并在重连后重新获取权威快照；不能让慢网页无限占用 EA。

## 9. 浏览器与缓存

网页共用一个连接管理器和行情缓存，多图表订阅复用它。进入本机模式后，图表与交易卡片不再通过 `/api/live` 获取该账户的实时状态；云端历史复盘保持原查询逻辑，并在界面标明来源，不能把朋友的云端交易快照混成本机账户。

生产网站使用 HTTPS。CSP 精确允许本机 WS 端点，不使用 `connect-src *`。新浏览器对公网页面访问回环网络有权限要求，具体版本、拒绝后恢复、VPN/代理影响均需要实际验收。不以关闭浏览器安全选项、安装根证书或共享 TLS 私钥作为安装步骤。

本机连接失败时保持只读并说明原因，不自动经云端下单。缓存 UI 不改变网站 Origin，也不绕过权限。

Service Worker 离线缓存作为后续独立功能：只缓存版本化 UI 资源，不缓存 API 私人响应、配对凭据或订单请求，不注册交易后台重试。首版不宣称网站离线后仍可重新打开并交易；后续上线离线模式需单独定义本地授权有效期、升级和撤销策略。

## 10. 可选云端同步

本机模式默认不增加任何上传。现有用户主动启用的旧 EA/bridge 同步继续按原配置工作，新功能不能假称它们已停止。

未来用户显式开启分享后，建议由浏览器按字段白名单异步上传所选成交、复盘 K 线和笔记，复用现有网站权限与采集接口。授权范围、账户标识和接收者需可见，关闭后停止后续上传；已上传内容的删除是另一项明确操作。

网页关闭时浏览器同步暂停。若需要全天候归档，须另行选择 EA 非阻塞上传或常驻进程，不能在交易 EA 中加入长时间阻塞的 WebRequest，也不能承诺首版兼得后台上传。

## 11. 实施顺序和发布边界

1. 固定本机协议，完成 EA 编译、回环监听、来源检查、配对和只读快照。
2. 网页共用连接接入图表与持仓，新增源码下载和安装页，保留原有复盘与社区功能。
3. 在模拟账户验证本地风控、全部已支持交易动作、去重、超时核查、账户切换和重启。
4. 通过 Git 发布 UI 和源码；每位用户自行编译安装，服务器部署不会给用户电脑自动安装或升级 EA。
5. 浏览器/MT5 真机验收完成后再标记交易功能可用。可选上传、离线 UI 和远程访问单独迭代。

前端与 EA 用协议版本/能力字段协商。旧版不支持的操作禁用，主协议不兼容时拒绝交易并给出源码更新入口。不能让网站自动升级后静默改变旧 EA 的本地风控。

## 12. 延迟指标和验收

记录三个相互独立的指标：浏览器往返 EA 的 ping RTT；EA 收到命令到开始提交 MT5 的本机处理时间；点击到券商最终回报的端到端时间。跨进程时钟不能直接相减，浏览器端到端使用自己的单调时钟，EA 内部耗时由 EA 单独报告。

至少报告 p50 / p95 / p99、超时数、失败/拒绝样本、电脑与 MT5 版本、券商服务器和网络环境。测试数据不上传真实密码。先测量再确定性能门槛；不承诺 1ms 或单一固定成交时延。

MQL5 实时毫秒定时器通常受约 10–16ms 事件生成间隔限制，忙碌时可能更久。大历史初始化、同步 OrderSend、日志写入、慢浏览器都必须纳入测试，不能仅测试空闲 ping。取消云端中转无法取消 MT5 到券商的网络与执行时间。

| 验收项 | 可观察结果 |
|---|---|
| 干净安装 | 仅安装 MT5 和浏览器，自编译源码后可连接；无 Python/代理进程 |
| 来源与配对 | 错误/缺失 Origin、错误/过期配对码、未本地确认、无效 token 均不能读私有数据或交易 |
| 默认只读 | 未在 EA 开交易权限时，网页无法通过改请求参数绕过 |
| 数据准确 | bid/ask、品种后缀、精度、手数、账户、四周期 K 线和持仓与 MT5 对照一致 |
| 模拟账户交易 | 支持的开仓/平仓/撤单/改单得到对应券商结果，部分成交和拒绝单准确呈现 |
| 故障恢复 | 发送前后断线、EA/浏览器重启、重复 ID/冲突参数不触发自动重复交易；未知状态可查询 |
| 账户与用户隔离 | 两台电脑各连自己 MT5；切账号撤销令牌；云端好友数据不串入本机模式 |
| 负载与调度 | 多窗格、加载历史、慢网络和慢浏览器不会造成无限队列；报告本机处理分布 |
| 网站发布 | 原登录/复盘/分享测试通过；HTTPS、CSP、源码下载、实际远端 Git revision 与健康检查一致 |

本机模拟协议测试可以验证前端逻辑，但不能替代真实 MetaEditor 编译、实际浏览器到 EA 连接和模拟账户验收。尚未完成的项目必须在发布记录中保留。
